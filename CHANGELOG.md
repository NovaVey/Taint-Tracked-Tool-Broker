# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [SemVer](https://semver.org/), with the pre-1.0 caveat that a minor release may still include a breaking change while the public API stabilizes.

## [Unreleased]

### Added

- **`ToolExecutor.destinationKeys` — `findOutboundHosts`'s `destinationKeys` narrowing is now wired into `BrokerOptions.allowedOutboundHosts` itself** (`src/types.ts`, `src/broker.ts`, GAPS.md #18, DESIGN.md §7.4). `findOutboundHosts()` (`taint/egress.ts`) already supported an optional `destinationKeys` option to scope its scan to just the argument key(s) that actually carry a call's destination instead of every string leaf in the tree — but it was previously only reachable by calling `findOutboundHosts` directly; `broker.ts`'s own EXFIL gating call site always called it unscoped. A tool now declares `destinationKeys?: readonly string[]` on itself at `register()`/`wrap()` time — the same "travels with the tool, no per-call config" shape `isSource`/`trusted`/`readsPrivateData`/`mayCallSummarize` already have — and `gateDecision()` threads it straight through as `findOutboundHosts(argsSnapshot, { destinationKeys: tool.destinationKeys })`. This closes a real false-positive shape: without it, a benign field whose value merely happens to be, in its entirety, a URL or email address (e.g. a chat tool's `text` body that is exactly a wiki link) trips the same unconditional hard `BLOCK` as a genuine disallowed destination, even though the tool never actually contacts that host. **Purely additive and non-breaking**: a tool that leaves `destinationKeys` unset gets the exact same unscoped whole-tree scan every existing registered tool already gets today — no existing tool's gating behavior changes. New `test/broker.spec.ts` coverage (`ToolExecutor.destinationKeys narrowing (GAPS.md #18)`) proves both directions: a tool without `destinationKeys` still gets the original whole-tree scan (a benign URL-shaped field elsewhere still trips a `BLOCK`), and a tool with `destinationKeys` declared no longer false-positives on that same benign field while still catching a genuinely disallowed destination under the named key.
- **`defaultPolicy` now actually constructs `QUARANTINE_AND_RETRY`** (`src/policy/default-policy.ts`), closing the doc/code gap the previous release's own `[0.3.0]` entry below tracked honestly rather than shipped (see GAPS.md's former "Not yet implemented" entry): whenever the decision the rest of the policy matrix (DESIGN.md §7.2) would otherwise produce is `BLOCK` or `REQUIRE_APPROVAL` **and** `TaintContext.matchedRecords` names a specifically identifiable untrusted source — an `'exact'` fingerprint match, or a `'simhash'`/`'shingle'` fuzzy match scoring at or above a deliberately conservative bar (well above the registry's own default fuzzy-match threshold) — `QUARANTINE_AND_RETRY` now REPLACES that verdict, naming the matched source in `reason` so whatever handles the verdict knows exactly what to re-run through `broker.summarize()`. A bare watermark taint with no such match (the common case for the load-bearing paraphrase-bypass scenario DESIGN.md §6.1 is built around) is untouched — the ordinary `BLOCK`/`REQUIRE_APPROVAL` verdict still stands, since there is nothing concrete to suggest quarantining. `src/broker.ts` required no changes: `finalizeGated()` already treated any non-`ALLOW`/`ALLOW_WITH_WARNING`/approved-`REQUIRE_APPROVAL` decision generically (never executed, always audited, thrown via `ToolCallBlockedError`), so `QUARANTINE_AND_RETRY` was already handled correctly end-to-end the moment `defaultPolicy` started producing it — verified directly rather than assumed. `PolicyDecision`'s `suggestedSchemaId` field is documented (`src/types.ts`) as reserved for a future named-schema-registry feature this library does not have; `defaultPolicy` never sets it, putting the whole actionable suggestion into `reason` instead. New `test/policy.spec.ts` coverage (the trigger condition, and each way it does NOT fire) and a new `quarantine-and-retry-offered` corpus pair (`corpus/cases.ts`) exercising both the positive and negative case through the real broker. DESIGN.md §7.2 and GAPS.md updated to describe the real, now-implemented trigger condition and its limits (entirely dependent on Layer 2 attribution succeeding — the same class of caveat GAPS.md already carries for fingerprint matching elsewhere).
- **A declared plan-freeze plan (`declarePlan()`, DESIGN.md §11) now survives `serializeBrokerState()`/`restoreBrokerState()`, including the exact cursor position it was at when exported** (`src/types.ts`, `src/persistence.ts`, `src/broker.ts`; GAPS.md #12's plan-persistence sub-gap, DESIGN.md §11's own note — both previously described this as a real, unfixed gap and are updated to describe the shipped mechanism). `SerializedBrokerState` gains two new optional fields, `plan: PlanStep[]` and `planCursor: number`, plus an explicit `schemaVersion` marker so this and any future wire-format extension has something to actually version against; a `SerializedBrokerState` exported before this feature shipped has none of the three and restores exactly as before (a safe no-op treated as "no plan"). "Resuming" means resuming exactly where the exporting broker left off: `serializeBrokerState()` reads a live broker's plan state via the new `ToolCallBroker.planState` accessor, and `restoreBrokerState()`'s returned `initialPlan` seeds a freshly-constructed broker with the SAME cursor (not step 0) via a new `BrokerOptions.initialPlan` construction-time option — deliberately a separate path from, and without touching, `declarePlan()`'s own `CLEAN`-only guard (still throws `PlanNotDeclarableError` exactly as before). **Safety property, verified rather than merely asserted**: restoring a plan — even a fully adversarially-tampered one, since `SerializedBrokerState` is externally-sourced input per `InvalidBrokerStateError`'s existing trust boundary — can only ever make future privileged calls MORE restrictive, never less, because plan-freeze itself is strictly additive (DESIGN.md §11): a call matching a (possibly bogus) plan step still has to clear the ordinary policy decision unchanged, and a non-matching call is rejected as unplanned regardless of a tampered plan's intent. `validateSerializedBrokerState()` extended accordingly (an array of plan-step-shaped objects; a non-negative cursor no greater than the plan's length; a `planCursor` without a `plan` rejected as malformed) — still SHAPE validation only, since per the safety property no plan CONTENT can turn into a policy bypass. Extensive new `test/persistence.spec.ts` coverage: a full mid-plan round trip (declare, partially advance, export, restore, confirm identical plan/cursor AND that the exact call rejected as unplanned on the original broker is also rejected on the restored one — the precise before/after this feature was meant to fix), backward compatibility with an old-shape/no-`schemaVersion` blob, a deliberately tampered-plan safety-property test, and malformed-shape rejection via `InvalidBrokerStateError`.

### Changed

- **`SerializedBrokerState`'s wire shape grows three new optional fields** (`schemaVersion`, `plan`, `planCursor` — see the plan-freeze persistence entry above). Flagged here explicitly even though it is purely additive and backward-compatible (an already-exported 0.x blob restores completely unchanged, still with no `schemaVersion`/`plan`/`planCursor`) because it IS a wire-format change: an integrator round-tripping a `SerializedBrokerState` through their own storage/transport with a strict/closed schema on that side (rather than TypeScript's structural typing) should be aware new fields can now appear in `serializeBrokerState()`'s output.

## [0.3.0] - 2026-08-31

### Security

A two-pass, multi-agent adversarial review (11 dimensions, then a second, deliberately different-in-kind 8 dimensions — active exploit construction, concurrency stress, DoS/resource-exhaustion among them) of the entire repository found three genuine critical-severity defects, all in `src/broker.ts`. None are content-matching evasions or gating-policy holes — like every prior review pass, they're correctness/robustness defects in code paths adjacent to the safety-critical ones, this time load-bearing enough to warrant this section rather than "Fixed" below. See DESIGN.md's own implementation notes (§ "a stale gating decision could still execute", § "one broker instance is one session") for the full before/after and the regression that caught a flawed first attempt at the fix.

- **A caller mutating the args object it passed to `call()` AFTER calling it (e.g. during a `REQUIRE_APPROVAL` wait) could change what actually executed without changing what the approval channel was shown or what got audited.** `execute()` used to get its own clone re-derived from the LIVE `args` reference at the moment it actually ran, not from the frozen `argsSnapshot` every other consumer (policy/approval/audit) already used — the exact divergence GAPS.md #16's snapshotting was supposed to close, reopened by one call site never actually reading from the snapshot. Fixed: every `execute()` call site now clones from `argsSnapshot`.
- **A watermark escalation landing during an async gap — `markContextExposure()` (never lock-protected by design, GAPS.md #1) racing a slow custom `PolicyFn`'s own `await`, or any concurrently-dispatched source call racing a `REQUIRE_APPROVAL` wait — let a decision computed against a now-stale, too-permissive `TaintContext` still execute.** Compounding this: `REQUIRE_APPROVAL` held the whole-broker lock for the ENTIRE approval wait, a potentially human-timescale operation, freezing every other call on the broker for its full duration. Fixed together: the gated dispatch path now revalidates against the CURRENT watermark immediately before ever calling `execute()`, discarding a stale decision and computing a fresh one if it moved; the lock is now released around a `REQUIRE_APPROVAL` wait specifically (never for the ordinary no-approval-needed case, which stays inside one unbroken lock hold to avoid reopening the ordering guarantee that fix's own first attempt broke — caught by an existing regression test before shipping).
- **Nothing stopped an integrator from sharing one `Broker` instance across two concurrent, unrelated agent sessions** — every safety guarantee here (the watermark, the Layer 2 registry, `withLock`'s ordering) is per-instance state, so doing this silently cross-contaminates or falsely gates one session off the other's exposure, rather than failing loud. Not detectable from inside `call()` itself; `createBroker()`, `BrokerOptions.sessionId`, `ToolCallBroker`, README.md, and new **GAPS.md #19** now document the one-instance-one-session rule prominently and explain exactly why violating it is unsafe.

### Fixed

- **`wordShingles()` (`taint/fingerprint.ts`) silently defeated fuzzy matching for short (< 5-word) near-duplicate text.** Its fallback treated an entire short text as one whole-text shingle, so two near-identical short payloads — a URL, an account number, a short instruction — differing only by word order or a single word scored EXACTLY 0 overlap, a full miss rather than a partial one, for exactly the shortest and most common realistic payload shape. Now shingles at the largest narrower width that still yields overlapping windows. GAPS.md #8 documents the fix and its own remaining (structural, not fixable without a real storage-cost tradeoff) limitation.
- **`InMemoryTaintRegistry`'s fuzzy-lookup candidate set had no upper bound before the expensive exact-scoring pass.** A registry containing a large cluster of near-duplicate or coincidentally-shingle-colliding records (a realistic adversarial shape) could make a single LSH band or shingle bucket collect a large fraction of the whole registry, silently degrading every subsequent `lookupFuzzy()` call's cost back toward the linear scan the indexing exists to avoid — `FuzzyLookupOpts.maxMatches` only ever bounded the *returned* list, not the *candidate* set scored to produce it. New `InMemoryTaintRegistryOpts.maxFuzzyCandidatesPerLookup` (default 2000) bounds it directly. GAPS.md #13 updated.
- **`scanArgsForTaint()`, `findOutboundHosts()`, and `diffProposedArgs()` all recursed over an args tree with no depth bound.** A sufficiently deep tree (nested objects/arrays forwarded from, say, a prior tool's own deeply-nested JSON result) would overflow the JS call stack: an unpredictable-depth `RangeError` instead of a clean, documented, catchable failure — and on the mandatory scan path specifically, one that produced ZERO audit trail, since it happened before `gateDecision()` had a `TaintContext` to audit with. All three now throw the new `ArgsTooDeepError` at a fixed depth of 500; on the broker's mandatory scan/egress paths this is now caught and recorded as an audited `BLOCK` before re-throwing. GAPS.md #13 updated.
- **`ToolExecutor.trusted`'s own doc comment was misleading, and its worked-examples checklist wasn't actually shipped.** The inline JSDoc framed `trusted` as "deterministic/pure tools may opt out" — determinism has nothing to do with whether a tool's CONTENT is attacker-influenceable (a perfectly deterministic function can still pure-functionally echo an externally-sourced argument), and `trusted: true` is the single most consequential declaration in a `ToolExecutor` (it exempts a source from Layer 0 AND Layer 2 entirely, with no error and no audit trail). The JSDoc now names the real criterion directly. Separately, `docs/classifying-tools.md` — the checklist README.md and this same JSDoc both point to — and `examples/` were both missing from `package.json`'s `files` allowlist, so an installed (not cloned) copy of this package could never actually resolve those links; both now ship. GAPS.md #10 updated.
- **`.github/workflows/release.yml` now creates an actual GitHub Release**, not just a git tag, after a successful npm publish — a plain tag never got the repo's Releases page "Latest" badge, since that's a separate GitHub object a tag alone doesn't create. Uses the runner's preinstalled `gh` CLI (no new third-party Action) with `--generate-notes`; `permissions.contents` bumped from `read` to `write` accordingly.

A follow-up second-pass review (22 medium, 18 low, 1 nit) found and fixed the following, all across `src/`, `corpus/`, `test/`, `examples/`, `bench/`, and CI:

- **A source call's own post-execution effects (raising the watermark, `markPrivateDataSeen`, the escalator audit) could land on the WRONG scope if a concurrent, lock-free `startNewTurn()`/`declassify()` reassigned `this.currentScope` mid-flight** — the `NONE`-sinkClass dispatch path (barrier-exempt by design, §4.1) read `this.currentScope` again after its own `await`s instead of the scope it actually started in. Fixed by capturing the scope synchronously at the top of `dispatch()` and threading it explicitly through to where it's applied. **Separately, an audit event for an ALLOWed or approved call whose `execute()` throws was never recorded at all** — `executed` is now set, and the event recorded with `executed: true`, before `execute()` runs, matching `AuditEvent.executed`'s documented meaning ("policy let the call proceed to execute()", not "execute() completed without throwing"). **Separately, `declassify()` cleared the watermark but left a declared plan/`planCursor` in place**, unlike `startNewTurn()`'s equivalent reset — a stale plan surviving a manual declassify could spuriously block an unrelated later call on the now-clean scope; `declassify()` now resets the plan too, and its audit reason names when it discarded one.
- **Nothing in CI or the release workflow ever executed the actual compiled `dist/` output that gets published to npm** — every real check (`vitest`, `tsx`) transpiles `src/*.ts` via esbuild, a different code path from `tsc`'s own emit, so a regression confined purely to `tsc`'s compile could reach npm undetected. Added `scripts/smoke-test-dist.mjs`, a small dependency-free ESM script that imports `dist/index.js` directly and exercises one real gated call end-to-end; wired into both `ci.yml`'s `test` job and `release.yml`, right after their `npm run build` steps.
- **`.github/workflows/release.yml` had no recovery path if "Create GitHub Release" failed after `npm publish` already succeeded** — GitHub Actions' "re-run failed jobs" reruns the whole job, so `npm publish` would fail every time afterward with a 403 against the already-live version, permanently blocking the release step. Now checks `npm view <pkg>@<version>` first and skips a redundant publish when the version is already live, so a re-run reaches release creation instead.
- **`bench/minhash-sketch-tradeoff.ts` re-implemented `shingleHashesOf()` from scratch** instead of importing the identical function already exported by `src/taint/fingerprint.ts` — a future edit to the real implementation could have silently desynced the benchmark from the algorithm it exists to validate. Now imports it.
- **The injection corpus never exercised `summarize()`'s input-provenance mismatch check** (GAPS.md #4) — both existing quarantine cases passed byte-identical text through it. New case `quarantine-provenance-spoof-fabricated-text`. **The corpus also never exercised multi-step `declarePlan()` cursor advancement** — every `declarePlan()` call in the repo used a single-element plan. New case `plan-freeze-multi-step-cursor-advances-then-rejects`, which also wires the previously-dead `save_draft` fixture into a real case for the first time. `corpus/schema.ts`'s `runCorpusCase()` now always surfaces the underlying error's `.message` into `CorpusOutcome.failureDetail` as a fallback (previously only 3 of 12 exported error types were special-cased; anything else collapsed to an opaque `decision: expected X, got ERROR`). `run-corpus.ts`'s dead `attackClass.endsWith('-known-gap')` disjunct (never true — no attack class uses that suffix) was removed, and the true-known-gap case-id list is now one exported `TRUE_GAP_IDS` constant (`corpus/cases.ts`) shared by `run-corpus.ts` and `test/corpus.spec.ts` instead of duplicated independently in each. Corpus is now 19 cases across 14 attack classes (was 17/13).
- **`examples/mcp-integration.ts`'s header claimed to demonstrate all three MCP protocol surfaces, but `resources/read` was prose only, never runnable code.** Added a real `demonstrateResourceRead()` alongside the existing `tools/call`/`tools/list` demonstrations; `McpClient` gained a matching `readResource()` method.
- **`examples/vercel-ai-sdk-integration.ts`'s final error-handling branch mislabeled any non-`ToolCallBlockedError` dispatch failure (e.g. a typo'd tool name) as `"UNEXPECTED: call was allowed"`**, silently dropping the real error — unlike every other framework-integration example in `examples/`, which correctly re-throws an unrecognized error. Fixed to match the established pattern, with a new demonstration exercising the corrected path.
- **`createDeferredApprovalChannel()`'s pending map silently overwrote an existing entry on an `approvalToken` collision**, permanently orphaning the earlier request's promise (no error, no way to ever resolve it). Now throws the new `DuplicateApprovalTokenError` immediately instead. **Separately, a `timeoutMs` timer was still scheduled (and never cleared) even when `onPending` synchronously resolved the request itself**, holding the event loop open for no purpose; the scheduling is now skipped once the request has already settled.
- **`jsonSafeClone` had no cycle detection**, unlike `structuredClone` it's positioned as a faster alternative to — a self-referential plain object or array recursed forever and crashed with an undocumented `RangeError` instead of this module's own promised clean `TypeError`. Fixed via the same `WeakSet`-based ancestor-guard pattern `taint/scan.ts` already uses. GAPS.md #16 updated.
- **`restoreBrokerState()` trusted externally-sourced `SerializedBrokerState` at its declared TypeScript type with zero runtime validation** — a malformed `watermark.level` restored "successfully" and only crashed, with an opaque raw `TypeError`, on a later unrelated gated call. Now validated at the restore boundary and rejected immediately with the new, descriptive `InvalidBrokerStateError`. **Separately, `src/persistence.ts`'s header documented that a declared plan doesn't survive a restore, but not that `resetScope:'turn-decay'`'s decay counter is silently reset too** (the same class of gap, but fail-safe — it can only delay, never hasten, when the watermark clears); now documented alongside it.
- **`src/policy/default-policy.ts`'s `QUARANTINE_AND_RETRY` case is unreachable — `defaultPolicy` never actually constructs one — but DESIGN.md §7.2 described it as an active behavior.** Corrected in DESIGN.md and tracked honestly in GAPS.md's "Not yet implemented" section instead of left as an undocumented doc/code mismatch; a new characterization test locks in today's true behavior so a future change that starts producing this verdict without a deliberate docs update fails loudly.
- **`findOutboundHosts()` scanned every string value anywhere in an EXFIL call's argument tree with no notion of which key is the actual destination**, so a benign field whose value merely happened to be a bare URL or email address triggered the same hard `BLOCK` as a genuine disallowed destination. Documented honestly in GAPS.md #18 and DESIGN.md §7.4; also fixed additively via the new opt-in `destinationKeys` option (see Added below). **Separately, `isAllowedOutboundHost()`'s array-allowlist path re-normalized and linearly rescanned the whole allowlist on every call** — now cached per allowlist-array-reference via `WeakMap`, removing multi-millisecond-per-lookup overhead at large allowlist sizes.
- **`exactHash()` hashed text via Node's lossy UTF-8 encoding, so two distinct strings differing only in which invalid lone/unpaired UTF-16 surrogate they contained could hash identically** — a genuine `TaintRecord.id` collision. Fixed with a narrowly-scoped pre-processing step that is a byte-for-byte no-op for every well-formed string. **Separately, any text made entirely of punctuation/symbols/emoji normalized to the empty string, making two completely unrelated symbol-only texts register as a "perfect" simhash match** — fixed with a new character-level shingling fallback. GAPS.md #8 updated; neither fix is load-bearing for the Layer 0 gate.
- **`sinkClassOf()`'s documented "most severe capability wins" precedence had zero test coverage anywhere in the repository.** **`FuzzyLookupOpts.maxMatches` was never validated**: `0` silently discarded every match (undermining the "highest-severity match always survives" guarantee) and a negative value crashed `lookupFuzzy()`/`lookupCombined()` with an uncaught `RangeError`; both now throw a descriptive `RangeError` for any non-positive-integer value.
- **`scanArgsForTaint()`'s mandatory pre-dispatch scan was structurally blind to tainted content nested inside a `Map` or `Set`** — its generic-object fallback walks only `Object.entries()`, which returns zero entries for either, and the broker's default `structuredClone`-based `cloneArgs` preserves both intact. Fixed with explicit `Map`/`Set` traversal branches ahead of the generic fallback. **Separately, the scan's Layer-1 `TaintedValue` fast-path branch had zero test coverage anywhere in the suite.**
- **`mapTainted()` silently dropped per-element taint when given an array of individually-wrapped `TaintedValue` elements** (rather than one array-level-wrapped `TaintedValue`) — a perfectly natural, type-checked call shape that previously fell through to `level: 'CLEAN'`. Now aggregates both shapes. **Separately, `taintAwareJSONStringify()` silently corrupted a `Date`/`Map`/`Set` value into `"{}"` instead of the value plain `JSON.stringify` would produce** — `Date` now delegates to its own `toJSON()` (matching native behavior); a `Map`/`Set` (which can hold live `TaintedValue` entries invisible to a naive walk) now throws instead of silently dropping any taint nested inside it.

### Changed

- **Breaking: `FuzzyLookupOpts.jaccardMin` (`src/types.ts`) has been renamed to `overlapMin`.** No backward-compatible alias — a pre-1.0 clean rename per this changelog's own versioning policy. Reason: the option was always an overlap coefficient (`|A∩B| / min(|A|,|B|)`), never a Jaccard index (`|A∩B| / |A∪B|`), and the two diverge sharply on size-imbalanced sets — exactly the "short excerpt in a large document" scenario this option tunes. Any caller passing `{ jaccardMin: ... }` to `lookupFuzzy()`/`lookupCombined()` must update to `{ overlapMin: ... }`. DESIGN.md and GAPS.md updated throughout.

### Added

- **`allowedOutboundHosts` now also detects email-address destinations, not just `http(s)` URLs** (`taint/egress.ts`'s `findOutboundHosts`, GAPS.md #18): a `net:email` sink's recipient carries no scheme at all, so it was previously the single most consequential blind spot named in that gap entry — the flagship example GAPS.md #18 itself opened with. Uses an anchored (whole-string) email-address pattern, deliberately more conservative than a generic "looks like a hostname" heuristic (considered and rejected — too high a false-positive risk for a hard-`BLOCK`-capable check, unlike this library's advisory-only `warnOnLikely*` heuristics). New corpus case `egress-allowlist-blocks-unapproved-email-recipient` demonstrates the distinguishing behavior via `send_email`, alongside the existing URL-based case. GAPS.md #18 and DESIGN.md §7.4 updated to name exactly what's newly covered and what still isn't (a bare hostname with no scheme and no `@`, or a destination assembled across multiple argument fields, remain invisible on purpose).
- **`findOutboundHosts(args, { destinationKeys })`** (`taint/egress.ts`): an optional, additive `destinationKeys: readonly string[]` list naming the argument key(s) that actually carry a tool's destination — when supplied, only those keys' subtrees are scanned instead of the whole argument tree, eliminating false-positive hard-`BLOCK`s from a benign field whose value merely happens to be a bare URL or email address. Omitting it preserves the original whole-tree scan exactly; not yet threaded through `BrokerOptions.allowedOutboundHosts` itself. GAPS.md #18 and DESIGN.md §7.4 updated.
- **`DuplicateApprovalTokenError`** (`src/approval.ts`, now re-exported from `src/index.ts`) — thrown by `requestApproval()` on an `approvalToken` collision instead of silently orphaning the earlier request (see Fixed above).
- **`InvalidBrokerStateError`** (`src/persistence.ts`, now re-exported from `src/index.ts`) — thrown by `restoreBrokerState()` for a malformed `SerializedBrokerState` instead of a delayed, opaque crash on a later call (see Fixed above).
- **`package.json`'s shipped `files` list now also includes `CONTRIBUTING.md`, `SECURITY.md`, and `CODE_OF_CONDUCT.md`**, so an installed (not cloned) copy of this package can resolve links to them, matching the fix already made for `docs/`/`examples/` above.

## [0.2.0] - 2026-08-30

### Added

- **Test coverage reporting** (`npm run coverage`, `vitest.config.ts`): v8-provider coverage over `src/**`, enforced in CI as a real gate (a dedicated `coverage` job, separate from the Node 20/22/24 test matrix) rather than just a report — thresholds are set a few points below the actual measured coverage as of this change (statements 96.32% / branches 91.82% / functions 99.21% / lines 98.03%) so a genuine regression fails CI without ordinary refactors tripping it.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and `.github/ISSUE_TEMPLATE/`/`PULL_REQUEST_TEMPLATE.md` — standard public-OSS-package community files, added now that `v0.1.0` is published.
- **Linting and formatting** (`npm run lint`, `npm run format`, `eslint.config.js`, `.prettierrc.json`): type-aware ESLint (`typescript-eslint`'s `recommendedTypeChecked`, plus `@typescript-eslint/no-floating-promises` turned on given how much of this codebase's correctness rests on exact async/lock ordering) and Prettier, both enforced in CI as a dedicated `lint` job. Fixed everything the initial run found rather than suppressing it: a `String()` on an `unknown` caught error that would have silently printed `[object Object]` in the corpus runner's failure output, two real `any`-typed-value leaks (`Object.getPrototypeOf`'s untyped return; a `Map` array literal inferred `Map<any, any>[]`), and an unbound method reference in `registerRawForQuarantine()` that could have broken an integrator's `execute()` if it used `this` internally — plus a handful of dead type assertions. Two eslint-disable comments survive (one `unbound-method`, one `no-unnecessary-type-assertion`), each narrowly scoped to a single line with an explanation of why it's a verified false positive rather than a real finding.
- **Counterfactual corpus baseline** (`corpus/schema.ts`'s `runUnprotectedCase`, `npm run corpus`'s new summary line): every corpus case's sink call(s), replayed against the same fixtures with no broker mediating them at all, alongside the existing protected run — makes "N/M passed" falsifiable instead of just a number: the report now says how many cases would have executed their sink call unprotected, and of those, how many the broker's actual decision would have stopped versus let through (split by the sanctioned-quarantine case and the two documented true known gaps). `test/corpus.spec.ts` locks the "would have executed unprotected" half in as a regression test.
- **Docs**: two new DESIGN.md §6 implementation notes, no code — what `broker.summarize()` approximates and where it stops short of a full privileged/quarantined dual-model split (§6.2's existing "mirroring CaMeL's quarantined Q-LLM" reference, made precise), and counterfactual argument diffing as a named research direction (not a shipped feature) for establishing genuine causal influence rather than exposure, cross-referenced from GAPS.md #15's overclaiming disclaimer.
- **`BrokerOptions.allowedOutboundHosts`** (DESIGN.md §7.4): an opt-in outbound-host allowlist for `EXFIL`-class sink calls — every such call's arguments are scanned (`taint/egress.ts`'s new `findOutboundHosts`/`isAllowedOutboundHost`) for genuine `http(s)` URLs, and one whose host isn't allowlisted is rejected with the new `DisallowedOutboundHostError`. A pure firewall-style rule, additive alongside plan-freeze in `dispatch()` rather than routed through `TaintContext`/`defaultPolicy` — applies uniformly regardless of the configured `PolicyFn`, and even to a `CLEAN` scope, since the point of an explicit allowlist is a structural boundary rather than another `REQUIRE_APPROVAL` prompt (GAPS.md #7's fatigue risk). Deliberately narrow in scope (GAPS.md #18 names exactly what it does and doesn't cover — most importantly, a call with no `http(s)` URL argument at all is invisible to it). New corpus case `egress-allowlist-blocks-unapproved-host` (attack class `unapproved-egress-host`) demonstrates the distinguishing behavior: blocking on an otherwise-`CLEAN` scope where the default policy alone would `ALLOW`.
- **`examples/mcp-sdk-integration.ts`** (`npm run example:mcp-sdk`): the same `tools/call` wrapping and tools/list rug-pull-guard pattern as `examples/mcp-integration.ts`, but against a genuine `@modelcontextprotocol/sdk` `McpServer`/`Client` pair connected via the SDK's own `InMemoryTransport.createLinkedPair()` — real JSON-RPC request/response and a real server-side `RegisteredTool.update()` description rewrite, not a hand-rolled mock, while staying offline (no real network socket) like every other example. `@modelcontextprotocol/sdk` and `zod` are added as devDependencies used only by this one example file; the library's own runtime dependencies remain empty.
- **Docs + tests, no code**: `DESIGN.md` §6.2's dual-model-split note previously said the Q-LLM's tool-access isolation is not something this library enforces. It turns out it already was, as a side effect of GAPS.md #17's reentrancy guard: a `QuarantineImpl` callback attempting `broker.call()` (top-level or nested inside a composite fetch-and-quarantine tool) is rejected with `ReentrantCallError`, same as a tool's `execute()` re-entering the broker. New regression tests in `test/broker.spec.ts` prove this rather than just asserting it; `ReentrantCallError`'s message now names the quarantine-callback scenario alongside the original tool-execute() one.
- **`diffProposedArgs()`** (`src/taint/counterfactual-diff.ts`, GAPS.md #15): a pure, stateless structural diff between two proposed tool-call argument trees — the shipped half of the "counterfactual argument diffing" research direction DESIGN.md §6 already named. An integrator who has done their own counterfactual re-run (re-invoking their model with tainted content excised — this library has no model access to do that part itself) calls this to get precise, path-tagged diffs (the same dotted/bracketed convention as `TaintMatch.argPath`) between what was actually proposed and what the re-run proposed, instead of hand-writing the tree-walking themselves. Purely diagnostic: never touches the broker, a scope, or any policy decision. `Date`/`RegExp` are compared by content; any other non-plain value (`Map`, `Set`, a class instance) by reference rather than silently misrepresented via naive key-enumeration (the same failure mode `jsonSafeClone()` fails loud on instead of risking) — reference equality can only ever over-report a divergence, never hide a real one.
- **`BrokerOptions.warnOnLikelyUnclassifiedSink`** (GAPS.md #10): an opt-in advisory heuristic mirroring `warnOnLikelyUnmarkedSource` (GAPS.md #1) for the mirror-image gap — flags, via an `ALLOW_WITH_WARNING` `AuditEvent` at `register()`/`wrap()` time, a tool declared with empty `capabilities` (`sinkClass: 'NONE'`, invisible to every policy check) whose `name` contains a keyword (`write`, `delete`, `exec`, `send`, `purchase`, ... — tunable, `true` uses a sensible default list) that often indicates a mutating/dangerous action. The common real-world trigger this narrows: an ordinary tool whose `capabilities` array was simply left empty by mistake, not a deliberately-deceptive one — GAPS.md #10 is explicit that this heuristic cannot catch the latter, or a tool whose real behavior doesn't show up in its name at all. Purely advisory: never changes what's registered or gates anything on its own. New reserved synthetic tool name `__tttb_registration_warning` for this event.

## [0.1.0] - 2026-08-30

First published release. Everything below was built and validated (typecheck, unit tests, injection corpus, build) before this tag was cut — see `.github/workflows/release.yml` for the tag-triggered publish process that re-validates all of it once more before publishing.

### Added

- **Core broker** (`createBroker()`, `broker.register()`/`wrap()`/`call()`): the scope watermark (`CLEAN < DERIVED_UNTRUSTED < RAW_UNTRUSTED`) as the load-bearing safety boundary, raised atomically the instant an untrusted source tool's result is captured — before the model ever reads it — so gating survives paraphrase, translation, and decision-laundering. Sinks are classified `EXEC`/`MUTATE`/`EXFIL`/`NONE` by declared capability; a default policy matrix gates by watermark level and sink class, with `privateDataSeen` as an escalator (the "lethal trifecta"), never a gate on its own.
- **Fingerprint registry** (`InMemoryTaintRegistry`): exact-hash + LSH-banded simhash + word-shingle overlap matching, secondary and never load-bearing — it can only tighten a policy verdict, never loosen one. Indexed (not a linear scan) for fuzzy lookup; optional `maxEntries` bounds memory for long-running sessions; `FuzzyLookupOpts.maxMatches` and a tree-wide cap in `scanArgsForTaint()` bound how many matches a single lookup/scan can return, without ever dropping the highest-severity match.
- **`broker.summarize()`** — the sanctioned quarantine/condense path: a capability-less LLM call you supply, whose output the broker itself registers as `DERIVED_UNTRUSTED`, with input-provenance validation (length-ratio + asymmetric shingle-coverage checks) against the claimed source record.
- **`broker.declarePlan(steps)`** — optional, additive plan-freeze strict mode: commit to a tool-identity sequence before any untrusted read; a later privileged call that doesn't match the next committed step is rejected on top of, never instead of, the normal policy check.
- **`broker.markContextExposure()`** (plus the `markToolDescriptionExposure`/`markSystemPromptExposure`/`markPastedContentExposure` specializations) — the manual escape hatch for untrusted content reaching the model outside any tracked tool call (a poisoned tool/plugin description, an untrusted system-prompt fragment, pasted content).
- **Cross-process persistence** (`serializeBrokerState()`/`restoreBrokerState()`, `serializeRegistry()`/`restoreRegistry()`) — export/import a broker's watermark and registry as JSON-safe state across a process boundary (e.g. for a sub-agent or a resumed session).
- **`createDeferredApprovalChannel()`** — an `ApprovalChannel` for `REQUIRE_APPROVAL` decisions that need a real human in the loop (a webhook, a Slack approval, an approval-queue UI) rather than a synchronous decision.
- **`jsonSafeClone()`** — an opt-in, faster alternative to `structuredClone` for args snapshotting when tool arguments are plain JSON; throws (rather than silently misrepresenting) on Date/Map/Set/RegExp/class instances/functions/symbols/bigints.
- **Convenience API surface**: `callSafe()` (a non-throwing `call()`), `registerAll()`/`wrapAll()` (bulk registration over a name -> tool record), `defineSource()`/`defineSink()` (pure `ToolExecutor`-building sugar), `registerRawForQuarantine()` (operationalizes the fetch-and-quarantine composite-tool pattern, returning `{ text, taintRecordId }` ready for `summarize()`).
- **`ToolExecutor.mayCallSummarize`** — declare `true` on a composite fetch-and-quarantine tool whose own `execute()` calls `broker.summarize()` internally, so it's correctly excluded from the lock-barrier-exemption optimization (GAPS.md #17).
- **`resetScope: 'turn-decay'`** — a third watermark-reset mode between `'session'` (never clears) and `'turn'` (clears at the next turn boundary): persists the watermark across a configurable `turnDecayWindow` of consecutive turns with no new exposure before clearing, narrowing (not closing) the cross-turn latent-influence gap (GAPS.md #2) to a chosen, quantified size. `turnDecayWindow: 1` is exactly `'turn'`.
- **Narrowed lock barrier**: `Broker.withLock`'s full-serialization cost is now scoped — a call that can neither be gated (`sinkClass === 'NONE'`) nor raise/mutate the watermark (not an untrusted source, no `readsPrivateData`, and, since GAPS.md #17, not `mayCallSummarize`) bypasses the lock entirely, since it's provably inert to the state the lock protects.
- **Injection corpus** (`npm run corpus`, also run under `npm test`): 15 cases across 12 attack classes, including two true, asserted known gaps (not silently-passing tests), a plan-freeze case, and a `resetScope: 'turn-decay'` case showing the cross-turn gap narrowed rather than closed.
- **Docs**: `DESIGN.md` (full architecture and rationale, including the soundness gap the original judge-panel design process found and closed), `GAPS.md` (17 named, honest limitations), `docs/classifying-tools.md` (a checklist and worked examples for classifying less-obvious tools).
- **Examples**: `examples/basic-usage.ts`, `examples/mcp-integration.ts` (MCP protocol-surface wiring plus a tool-description rug-pull guard), `examples/anthropic-tool-loop.ts` (a full tool-calling loop, including `startNewTurn()`'s correct call site and a deferred-approval scenario), plus framework-integration examples for `examples/langchain-integration.ts`, `examples/vercel-ai-sdk-integration.ts`, and `examples/openai-agents-sdk-integration.ts` (each a structural stand-in for that framework's `tool()`/`execute()` shape, no real framework dependency required).
- **`bench/args-clone.ts`** (`npm run bench`) — `structuredClone` vs `jsonSafeClone` benchmark across representative args shapes.
- **`bench/minhash-sketch-tradeoff.ts`** (`npm run bench:minhash`) — the reproducible Monte Carlo measurement behind the decision *not* to ship fixed-size MinHash sketches for the registry (see GAPS.md #13 and DESIGN.md's implementation note): 35-79% false-negative rates at realistic document-size ratios even at a generous sketch size.
- **`.github/workflows/release.yml`** — tag-triggered (`v*`) npm publish with provenance, gated on the tag matching `package.json`'s version and a full re-run of typecheck/build/test/corpus.

### Fixed

A number of real bugs were found and fixed during development (adversarial review passes, a multi-agent improvement-roadmap review, and tests written for new features catching design gaps before they shipped) — see `DESIGN.md`'s "Implementation note" sections for the full, specific history of each, including exactly what was found, why it mattered, and what was deliberately *not* fixed and why.

### Known limitations

Not a soundness guarantee — a conservative, structural approximation with named, honest limits. See `GAPS.md` for the full list. `broker.summarize()` is now serialized against `broker.call()` under concurrent dispatch (GAPS.md #17, fixed) — with one named residual risk: a composite fetch-and-quarantine tool whose `execute()` calls `broker.summarize()` internally must declare `mayCallSummarize: true` (see `docs/classifying-tools.md` question 5) or it stays wrongly eligible for the lock-barrier-exemption optimization and the original race reopens for that one tool.
